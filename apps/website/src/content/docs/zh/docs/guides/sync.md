---
title: 同步
description: 通过一个你自己掌控的文件夹共享设置和聊天存档 —— iCloud Drive、OneDrive 或任何别的地方。
---

同步在你的设备之间搬运两样东西：你的**设置**和你的**聊天存档**。它通过一个普通文件夹工作，所以没有八千代账号，中间也没有服务器。macOS 推荐 iCloud Drive，Windows 推荐 OneDrive，但任何你自己保持同步的文件夹都一样能用。

在 **设置 → 同步** 里配置。

## 启用

1. 选一个文件夹 —— 使用当前平台的推荐同步目录，或者点**选择文件夹**自己挑。macOS 默认用 iCloud Drive，Windows 默认用 `<OneDrive>\Yachiyo\Sync`。
2. 点**启用同步**。

在第二台设备上，面板会改为提供**加入此设备**，因为那个文件夹里同步已经初始化过了。加入会把已有的存档拉下来。

推荐目录不可用时，在 macOS 登录 iCloud Drive，或在 Windows 登录 OneDrive。服务不存在时八千代不会伪造路径；也可以选择其他同步工具管理的任意文件夹。

## 同步什么，以及代价

**设置**是双向同步的。来自其他设备的**聊天存档**是**只读**的 —— 你可以在台式机上读一段从笔记本开始的对话，但没法在那里接着聊。线程始终归创建它的那台设备所有。

同步自己会跑：改动后有一次防抖的推送，加上周期性的拉取，并有单飞锁保证两趟不会重叠。不想等的时候，**立即同步**强制跑一趟。

## 冲突

两台设备改了同一项设置就会产生冲突，而八千代不去猜。**设置 → 同步 → 冲突** 会列出每一个冲突，附上有差异的字段、两个版本的哈希，以及按字段的解决方式：

- **保留本设备** —— 本地的值胜出。
- **使用同步版本** —— 用同步过来的设置替换本设备的。因为是破坏性的，应用前会先确认。
- **复制同步的 TOML** —— 把传入的版本拿出来自己检查。

一个冲突解决之后，那对确切的版本会被记住，于是同样的分歧不会在之后每一趟里再来烦你。

## 状态

面板会报告以下之一：

| 状态                 | 含义                         |
| -------------------- | ---------------------------- |
| **就绪**             | 同步正常工作                 |
| **本设备未启用**     | 文件夹里有同步；加入即可参与 |
| **未初始化**         | 这个文件夹里还没有配置过同步 |
| **需要处理**         | 有冲突在等你                 |
| **同步文件夹不可用** | 选中的文件夹访问不到         |

它还会显示设备数量和待处理的冲突数。

:::caution[同步文件夹应保持私密]
模型供应商 API key 和 Vertex 私钥只存在本机加密凭据库中，不参与同步。设置同步仍会复制 `config.toml`，而其中可能包含 Exa 网页搜索 API key 等其他敏感值。不要使用共享团队盘或公开链接。
:::
