---
title: 子智能体与编码智能体
description: 把工作委派给内置的 worker 子智能体，或通过 ACP 交给 Claude Code 和 Codex。
---

有些活儿不该待在主对话里 —— 一次会淹掉上下文窗口的全仓库搜索，或者一个值得有自己的智能体的多文件重构。`delegateTask` 工具把这类工作交出去，再把结果带回来。

委派有两种后端，全局二选一。

## Worker 模式（默认）

八千代自己跑子智能体，用的是你配置的供应商。四个具名智能体，各有固定角色：

| 智能体      | 用来干什么                                                                     |
| ----------- | ------------------------------------------------------------------------------ |
| **Explore** | 找文件、搜模式、搞清楚某个东西怎么运作。只读。模块彼此独立时可以并行跑好几个。 |
| **Plan**    | 为一次复杂的多文件改动给出分步策略，并指出关键文件。                           |
| **Review**  | 在提交之前，对未提交的改动给出第二意见。                                       |
| **General** | 编辑、执行命令，以及只读智能体做不了的一切。兜底选项。                         |

四个默认都启用。在 **设置 → 能力 → 编码智能体** 里决定哪些可用。

Worker 任务是异步的。Worker 启动后，`delegateTask` 会立即返回 Task ID。主智能体需要查看当前状态、最近进度、输出或错误时使用 `getTask`；要补充要求或唤醒 idle 任务时，使用带该 ID 的 `steerTask`。Worker 向 parent 或同组任务通信也使用 `steerTask`。每轮完成、空输出和网络重试耗尽都会自动报告给主智能体。

:::note[子智能体是从零开始的]
一个 worker 子智能体只看得到它的系统提示词和交给它的那段任务 —— 看不到你的对话，看不到方案文档，也看不到之前的工具结果。任务简报必须自包含，带明确的文件路径和完成标准。

这就是为什么「按上面的方案继续」会失败，而「在 `src/net/client.ts:120` 实现重试逻辑，保留现有的退避常量」能成。
:::

每个 worker 可以跑在自己的模型上 —— **设置 → 能力 → 编码智能体** 里每个 worker 都有一个模型选择器，默认跟随发起调用的那个模型。读操作繁重的 Explore 跑便宜模型、主对话留在强模型上，是最明显的用法。

## ACP 模式（已废弃）

另一种后端通过 [Agent Client Protocol](https://agentclientprotocol.com/) 把任务交给外部编码智能体 —— Claude Code、Codex，或者任何说 ACP 的东西。这个智能体作为独立进程运行，用自己的模型和上下文，然后把结果报告回线程。

:::caution[已废弃]
ACP 模式已废弃。现有配置为了兼容仍然可用，但开发投入都在 worker 模式上。不要基于它搭新的东西。
:::

有一份预配置的档案：

| 字段      | 值                                           |
| --------- | -------------------------------------------- |
| `name`    | Claude Code                                  |
| `command` | `npx`                                        |
| `args`    | `["-y", "@zed-industries/claude-agent-acp"]` |
| `env`     | `{ "ACP_PERMISSION_MODE": "acceptEdits" }`   |

在 ACP 模式下，除非工作区是一个 git 仓库，否则 `delegateTask` 不可用。让一个外部智能体改文件却没法 diff 也没法回滚，这笔买卖不划算，所以这个工具直接拒绝，而不是悄悄降级。

## 切换模式与管理档案

```bash
yachiyo agent mode worker      # 或者：acp
yachiyo agent list             # 当前模式，以及所有 ACP 档案
```

ACP 档案接受这些字段：

| 字段          | 类型                    | 说明                                    |
| ------------- | ----------------------- | --------------------------------------- |
| `id`          | `string`                | 添加时自动生成                          |
| `name`        | `string`                | 显示名称                                |
| `enabled`     | `boolean`               | 停用的档案留在配置里，但不会被提供      |
| `description` | `string`                | 界面上显示                              |
| `command`     | `string`                | 可执行文件 —— `npx`、`node`，或绝对路径 |
| `args`        | `string[]`              | 参数                                    |
| `env`         | `Record<string,string>` | 额外的环境变量                          |

细节见 [`agent` 命令行参考](/zh/docs/cli/agent/)。

## 或者干脆不委派

委不委派是一个判断，不是一个设置项。对于范围小又清晰的改动，主智能体自己干往往比写一份足够好的任务简报（好到能让一个看不见你对话的智能体照做）还要快 —— 那就直接把改动要求提出来。如果你希望这条边界是被强制而不是被默认的，探索和聊天[运行模式](/zh/docs/concepts/#运行模式)会把 `delegateTask` 从工具列表里彻底拿掉。
