## 这些我都得手动配吗？

不用，而且大多数情况下你不该手动配。八千代默认启用 `yachiyo-help` 技能 —— 关于它自己的命令行、配置和安装流程的文档 —— 外加 shell 权限。所以它可以自我管理：设置开机自启、修复 `PATH`、创建定时任务、整理模型列表、写一个技能。

用大白话说出来，然后检查它做了什么。这份文档存在的意义是：出问题的时候、你想了解底层细节的时候，或者你需要把它写进脚本的时候。

## 有 Windows 或 Linux 版本吗？

八千代支持 macOS 和 Windows 11 x64。Windows NSIS 安装包不签名，所以 **Unknown publisher（未知发布者）**提示是预期行为。Windows 10、Windows ARM 和 Linux 不是发布目标。

Windows v1 不提供 Activity/OCR、开机自启、保持唤醒、Kagete、Ghostty 控制、macOS 应用自动化和 macOS 截图技能。这些入口会在 Windows 上被过滤掉，而不是显示成无法使用的工具。

## 八千代支持 MCP 吗？

不支持，这是刻意的。取而代之的是 Markdown 文件形式的技能：没有协议，没有服务进程，没有清单文件。你会写 README，就能扩展八千代。整个取舍就在这里 —— 你放弃了一个生态量级的现成集成，换来一个你能读、能改、能推理的东西。

## 我的数据在哪？

在你机器上的 `~/.yachiyo`。对话存在本地 SQLite 数据库里。没有托管后端，也没有账号。见[文件与路径](/zh/docs/reference/paths/)。

## 有遥测吗？

没有。

## 能用本地模型吗？

能。**Ollama** 预设指向 `http://localhost:11434/v1`，不需要 key。任何兼容 OpenAI 的服务都一样。见[供应商与模型](/zh/docs/guides/providers/)。

## 能同时用多家供应商吗？

能，而且这就是预期用法。模型是按消息选的，不是按应用 —— 用便宜的起草，把难的问题升级上去，整段交流留在同一个线程里。

## 所有事情都得用同一个模型吗？

不必。聊天模型和[工具模型](/zh/docs/guides/providers/#工具模型)是分开的，后者负责线程标题、记忆蒸馏这类后台工作。把工具模型指向一个又小又快的模型是常规配置。

## 我的 Claude Code / Codex 技能能用吗？

能。八千代会连同自己的技能一起扫描 `~/.claude/skills`、`~/.codex/skills` 和 `~/.agents/skills`，主目录和每个已注册工作区里都扫。它们会被发现但不会自动启用 —— 在 **设置 → 能力 → 技能** 里打开。

## 我改内置技能的改动为什么没了？

`~/.yachiyo/skills/core/` 每次应用启动都会重新解压。自己的东西请放进 `~/.yachiyo/skills/custom/`。

## 应用关掉后定时任务还会跑吗？

不会。定时任务、频道机器人和 `yachiyo send` 都需要应用在运行。在 macOS 上，想让它一直在，可以配置 [LaunchAgent](/zh/docs/install/)。Windows v1 没有开机自启选项，需要手动启动应用并让它保持运行。

## 别人能通过 Telegram 用我的助手吗？

只有你允许才行。用户在首次接触时注册为 `pending`，在你放行之前一直被挡着。访客拿到的是沙箱工作区、过滤后的记忆、独立的档案和一份 token 配额。见[频道](/zh/docs/guides/channels/)。

## 机器人会在群里对所有消息都回话吗？

不会。群模式跑一个便宜的探针模型观察对话，只在有值得说的话时才唤醒完整模型，并按休眠、活跃、参与中三个阶段退避。见[群讨论模式](/zh/docs/guides/channels/#群讨论模式)。

## 能不让它改文件吗？

能。用**探索**或**聊天**[运行模式](/zh/docs/concepts/#运行模式)，这会把编辑类工具从模型的工具列表里彻底拿掉；或者干脆不给这个线程分配工作区。任何确实碰了文件的运行都会留下可复核的 diff。

## 我的 API key 安全吗？

模型供应商 API key 和 Vertex 私钥会加密存放在由操作系统保护的本机凭据库中。它们不会写进 `config.toml`，也不会被[同步](/zh/docs/guides/sync/)复制。命令行输出会把 API key 打码。

其他密钥有各自的规则：Exa 网页搜索 key 可能存在 `config.toml` 中，频道凭据则在 `channels.toml` 中。这两个文件都应保持私密。

## 对话太长了会怎样？

较早的上下文会被压缩而不是丢弃 —— 一份交接摘要保住线程的实质内容，同时腾出窗口。阈值可通过 `chat.stripCompactThresholdTokens` 配置。

## 能搜索旧对话吗？

能，在应用里或从命令行都行。全文索引基于 trigram，所以中文和英文一样能搜：

```bash
yachiyo thread search "那个关于重试的事" --limit 10
```

## 同步是不是意味着我能在任何设备上聊天？

部分是。设置是双向同步的，但来自其他设备的聊天存档是**只读**的 —— 你可以在台式机上读笔记本上的对话，但不能在那里接着聊。

## 我可以贡献代码吗？

欢迎 bug 修复和文档改进。功能 PR 除非先在 issue 里讨论并获得认可，否则不会被接受 —— 写代码之前先开 issue。见[仓库](https://github.com/ringotypowriter/yachiyo)。
